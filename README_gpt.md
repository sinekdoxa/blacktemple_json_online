# GitHub Pages: экспорт подписки в браузере

Выложите **только содержимое `web/`** в отдельный публичный репозиторий, например в корень ветки `main`. В Settings → Pages выберите Deploy from a branch → main → / (root). Откройте `https://USER.github.io/REPOSITORY/`. Публикация из этого рабочего каталога автоматически не выполнялась.

Не публикуйте весь проект декомпиляции, реальные подписки, identity-файлы, сохранённые ответы и экспорт. В файлах сайта нет пользовательских реквизитов. Общий HMAC-ключ протокола публичен, как и в Python-скрипте; скрыть его в статическом сайте невозможно.

## Как работает

- Web Crypto вычисляет HMAC-SHA256 того же сообщения, что и Python.
- Fetch отправляет GET непосредственно на введённый HTTPS URL, без cookie, Referer, редиректов и повторов. Максимум 4 MiB, таймаут 30 секунд.
- Ответ (`servers[].key`, страна и класс) преобразуется в массив отдельных Xray-профилей. Можно скачать массив или один объект профиля.
- QR генерируются локальной копией `qrcode-generator` 1.4.4 (MIT, Kazuhiko Arase), не через CDN/API. Данные сервера выводятся DOM-методами, без интерполяции в HTML.
- Ссылка и результаты остаются в оперативной памяти страницы. Нет аналитики, фоновой синхронизации, service worker и передачи данных автору страницы. Загрузки файлов сайта GitHub всё равно видит; сервер подписки видит IP, URL и идентификатор пользователя. Браузерные расширения и изменённый владельцем сайта JavaScript способны прочитать данные — это не защита от недоверенного кода.
- В IndexedDB хранится только постоянный синтетический `app_id`/HWID/device. Ошибки хранилища останавливают запрос, не создают временный HWID. Первый запуск нескольких вкладок сериализован транзакцией. Очистка данных, приватный режим, другой браузер, origin или устройство могут создать другую идентичность и занять слот подписки.
- Можно заранее импортировать `identity.private.json` из Python или экспортировать текущий идентификатор. Не распространять общий пользовательский identity со страницей. GitHub Pages проекты одного `USER.github.io` имеют общий origin и хранилище; лучше отдельный доверенный origin без чужих приложений.

## Важное ограничение: CORS

**Без разрешения сервера браузерный эквивалент Python невозможен.** Перед GET браузер отправляет OPTIONS на URL подписки, так как используются нестандартные заголовки. Это дополнительный сетевой запрос, не автоматический повтор GET.

Сервер должен успешно ответить на preflight, например:

```http
Access-Control-Allow-Origin: https://USER.github.io
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Allow-Headers: device, X-hwid, X-App-Id, X-Timestamp, X-Signature, Accept
Vary: Origin
```

`Access-Control-Allow-Origin` также нужен в GET-ответе, включая ошибки. Origin не содержит путь репозитория. OPTIONS обычно не должен требовать HMAC отсутствующего GET. Настраивать это может только владелец сервера. `mode: no-cors` не помогает: тело opaque-ответа недоступно, а нужные заголовки запрещены. Service worker, iframe, CORS-расширения и публичные прокси не являются безопасным решением.

Браузер сам задаёт `User-Agent`; надёжно подменить его на `Blacktemple/1.3.16` нельзя. Если backend требует именно этот UA, потребуется согласованная поддержка браузера сервером, а не изменение HTML. Также могут действовать серверные проверки Origin, HWID и другие неизвестные ограничения. Реальный запрос к подписке при разработке страницы не выполнялся; CORS и приём браузерного UA не подтверждены.

При запрете CORS остаётся локальный импорт **исходного ответа** из файла. Страница понимает JSON с `servers`, VLESS-строки и Base64, но не принимает обратно экспортированный массив Xray. Это резервный офлайн-сценарий, не обход серверного запрета.

## Совместимость и безопасность

Поддержаны TCP/raw, WS, gRPC, XHTTP, HTTPUpgrade, TLS/Reality, как в Python. Названия получают префикс страны/класса; параметры VLESS до `#` не меняются. Неизвестные параметры вызывают ошибку. JSON не является универсальным для sing-box, Clash и всех GUI-клиентов. Xray CLI принимает один объект. Для XHTTP необходимо совместимое ядро. Все профили используют порт 10808, одновременно их запускать без изменения портов нельзя. `allowInsecure` переносится из подписки: проверьте, не отключена ли проверка сертификатов.

Скачанный JSON, VLESS и QR содержат секреты доступа. Не публикуйте их. Кнопка очистки удаляет результаты из DOM, но не является гарантированным стиранием памяти браузера, буфера обмена или скачанных файлов. VPN-подключения и доступность серверов не проверяются.

## Локальная проверка

Из корня проекта:

```powershell
node --test tests/test_web.cjs
python -m http.server 8080 --directory web --bind 127.0.0.1
```

Откройте `http://localhost:8080`. Для сетевого запроса серверу также нужно разрешить этот Origin. `file://` не рекомендуется: ограничения безопасного контекста, хранилища и origin. Зависимости npm устанавливать не требуется. QR-библиотека включена в `vendor/`; при запуске сайт не обращается к источнику библиотеки.
